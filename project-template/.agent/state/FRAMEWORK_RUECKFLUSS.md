# Framework-Rückfluss

> Beobachtungen zum **Workflow selbst**, nicht zum Projekt: eine Regel in
> den Rollen-Dateien ist unklar oder widerspricht einer anderen, ein
> Werkzeug (`run-role.sh`, `vorflug.sh`, …) fehlt oder verhält sich
> anders als beschrieben, eine Eigenheit des Harness oder Modells stört
> den Ablauf. Der Orchestrator trägt ein – aus den `Workflow:`-Zeilen der
> Rückmeldungen und eigene Beobachtungen – und nennt neue Einträge beim
> Abschluss jeder Initiative.
>
> Rückweg: Der Nutzer legt diese Datei im Repo `agent-workflow` unter
> `input/` ab, dort wird sie verarbeitet. Danach entfernt er die
> übernommenen Einträge hier.
